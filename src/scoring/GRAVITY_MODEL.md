# План Максимум: охват аэропорта и гравитационная модель

Формулы и пороги ниже явно согласованы с пользователем: в присланных текстах
математические вставки отсутствовали. Модель не меняет `population_mln`, линейный
скоринг, DTO и принятую тройку кандидатов. Входы — актуальные Parquet Dev 1,
хеши сохранены в `reference/current_data.json` и метаданных каждого запуска.

## Эффективное население

`calculate_effective_population(df, lam=0.45) -> pd.Series`:

`P_eff = P_city + Σ [P_sat × exp(−λ × t)]`, только для `t ≤ 2 ч`.

`population_city_mln` — миллионы человек; числа в скобках `agglomeration_members`
— люди (запятая или пробел разделяет тысячи). Ядро учитывается целиком, как при
нулевом времени доступа. Это дополнительное допущение, а не измерение поездок
из всех кварталов города. Результат сохраняет исходный индекс, имеет имя
`effective_population_mln`; исходный DataFrame не изменяется.

| Спутник / аэропорт | Принятое время, ч |
|---|---:|
| Тольятти / KUF | 0,75 |
| Дзержинск / GOJ | 0,55 |
| Энгельс / GSV | 0,70 |
| Волжский / VOG | 0,60 |
| Пятигорск / MRV | 0,35 |
| Ессентуки / MRV | 0,55 |
| Кисловодск / MRV | 0,75 |
| Остальные перечисленные спутники / районы | 0,65 |

Словарь `AIRPORT_ACCESS_HOURS` включает код аэропорта, чтобы не смешивать
Волжский район Самары с городом Волжским. Времена предложены в задании и
приняты как допущения; дорожный роутер/GIS не использовался. Поэтому это
**сценарная оценка двухчасового охвата**, не фактически построенная изохрона.
В текущем словаре все перечисленные спутники попадают внутрь двух часов;
отсечение проверено тестом на границе 2,00 / 2,01 ч.

`lam` измеряется в 1/час; при `lam=0` все включённые спутники имеют вес 1.
Пустая строка означает явно заданное отсутствие спутников; пропуск, повтор
спутника и ошибка формата вызывают ошибку вместо молчаливого уменьшения массы.
Для λ=0,45 эффективное население Самары — 1,835678 млн, Казани — 1,610649 млн.

Слагаемые доступны в `series.attrs['catchment_details']` и `catchment_details.csv`.
`effective_population.csv` сохраняет эффективное население и сверку суммы
ядра со спутниками. У MRV исходная агломерация 0,648282 млн, но сумма
перечисленных компонентов 0,586898 млн: **разница 61 384 человека**.
Неописанные жители не добавляются автоматически; состав агломерации нужно
уточнить у Dev 1. Расхождение также сохраняется в `population_reconciliation`.

## Гравитация

`calculate_gravity_matrix(cities_df, routes_df=None, gamma=1.15) -> pd.DataFrame`:

`G_ij = P_eff_i × P_eff_j × sqrt(q_i × q_j) × W(d_ij) / [d_ij^γ × (1 + F_ij)]`.

- `q_i = avg_wage_rub_region_i / mean(avg_wage_rub_region)` по кандидатам;
  зарплата — прокси покупательской способности, не доход каждого пассажира.
- `d_ij` — гаверсинус по `lat/lon` аэропортов, R=6371 км. Параметр `gamma > 0`.
- `W=0` при `d ≤ 300` и `d ≥ 3000` км; `W=1` на `[800;1500]` км;
  на `(300;800)` и `(1500;3000)` — линейные переходы. Это принятый фильтр
  сценария для SJ-100, не подтверждение его сертифицированных ограничений.
- `F_ij` — `competitor_flights_weekly` именно направления А→Б. Отсутствующая
  пара/таблица или NaN дают 0 по согласованной модели. В отчёте отдельно
  записывается маска наблюдений: неизвестность не выдаётся за измеренное отсутствие
  конкурентов. Нулевая подстановка может завышать потенциал при неполных данных.
  `own_flights_weekly` не вычитаются и не считаются конкурентом.
- Вход может содержать готовое `effective_population_mln`; иначе оно вычисляется
  с `lam=0.45`. Для другого λ сначала передайте свой результат расчёта охвата.

Матрица содержит все пары, включая нулевую диагональ, в порядке входных IATA.
Без конкурентов она симметрична; направленные частоты могут нарушать симметрию.
Повтор одной пары в `routes_df` требует предварительной явной агрегации.
Входы не изменяются; нулевые расстояния не приводят к делению на ноль.

`gravity_hub_potential = matrix.sum(axis=1)`; то же значение доступно в
`matrix.attrs['gravity_hub_potential']`. Это относительный индекс потенциальных
связей с остальными 11 кандидатами, **не пассажиры, выручка или прогноз трансфера**.
Добавление городов меняет суммы и среднюю зарплату; сравнивать нужно одинаковые
наборы кандидатов. Модель — аналогия с законом Ньютона, не физический закон
авиаспроса и не доказательство оптимальности хаба.

## Результат без подгонки под ожидаемых лидеров

На обновлённых данных, с частотами из `routes_proof.parquet`, λ=0,45 и γ=1,15:

| Место среди 12 | Город | Индекс |
|---:|---|---:|
| 1 | Нижний Новгород (GOJ) | 0,005081 |
| 2 | Самара (KUF) | 0,004976 |
| 3 | Челябинск (CEK) | 0,004960 |
| 8 | Казань (KZN) | 0,003402 |

Согласованная модель **не подтверждает совместное лидерство Самары и Казани**.
В отчёте показан полученный результат без изменения коэффициентов под ожидаемую
тройку. Отдельно сохранены места всех 12 городов и места допустимых кандидатов
данной гипотезы; исключение SVX из кандидатов нового хаба не удаляет его из
возможных пунктов назначения матрицы. Линейная и гравитационная модели отвечают
на разные вопросы и используют разные признаки: общий профиль города и
потенциал конкретных связей с учётом расстояний и частот конкурентов.

## Вызов из ноутбука или дашборда

```python
from src.scoring.city_scorer import (
    load_features, calculate_effective_population, calculate_gravity_matrix,
)

cities = load_features()
cities['effective_population_mln'] = calculate_effective_population(cities, lam=0.45)
routes = load_features('data/processed/routes_proof.parquet')
matrix = calculate_gravity_matrix(cities, routes, gamma=1.15)
cities['gravity_hub_potential'] = cities.iata.map(matrix.sum(axis=1))
```

CLI с `--with-gravity` дополнительно сохраняет `effective_population.csv`,
`catchment_details.csv`, `gravity_matrix.csv`, `gravity_pairs.csv` (132 направления)
и `gravity_hub_potential.csv`. Метаданные содержат формулы, λ/γ, времена доезда,
хеши входов, правило нулевых частот и расхождения населения. При отсутствии
`--routes` все частоты считаются неизвестными и равными нулю по сценарию;
для воспроизведения опубликованного расчёта файл маршрутов обязателен.

Матрица и индекс не добавляются в замороженный `CityScoreDTO`; их можно получать
через отдельные функции. `effective_population.csv` — расширенная экспортная
таблица; исходные файлы `data/processed/` не перезаписываются.
