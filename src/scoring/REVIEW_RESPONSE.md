## Оставшаяся несогласованность Dev 3 / Dev 4

В src/ui/sidebar_controls.py фиксированный селектор предлагает KUF/GOJ/SVX.
В src/models/unit_economics.py evaluate_hypotheses допускает только хаб из
переданного текущего топ-3. При общей тройке SVX/KUF/KZN выбор GOJ вызывает:

`ValueError: Выбранный hub_iata отсутствует в Топ-3 городов`.

Это воспроизводится после исправления скоринга. При изменении весов такая
проблема может возникнуть и с другими фиксированными вариантами. Подгонка
топ-3 под селектор нарушила бы смысл скоринга.

Команде нужно выбрать одну совместимую семантику: Dev 4 строит варианты
селектора из текущего результата и сбрасывает недоступный выбор, либо Dev 3
разрешает анализ произвольного допустимого города полного лонглиста и Dev 4
передаёт полный список. В этом PR меняются только файлы Dev 2.

Автоматический режим выдаёт UserWarning, но Streamlit не обязан показывать
его пользователю. Dev 4 также должен вывести явную подпись preliminary и
ограничения данных: общий CityScoreDTO не содержит поля статуса.
Подпись критерия расстояния в UI также должна описывать расстояние до Москвы
и максимум на 1150 км: старое название про удалённость от нескольких хабов
не соответствует формуле, принятой по этому ревью.
