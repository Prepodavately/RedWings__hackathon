# Red Wings · Лаборатория маршрутной сети

Рабочий учебный прототип на Streamlit + Plotly. 4 вкладки: стратегии и сеть, рейтинг городов, чувствительность, данные. Числа по маршрутам и баллы городов СИНТЕТИЧЕСКИЕ. Рекомендацию для Red Wings по ним делать нельзя.

## Запуск (Windows, WSL, Linux, macOS)
Нужен Python 3.10+ (у Миши Python 3.12 подойдёт). Распакуйте архив, откройте терминал в папке с app.py:

```
python -m pip install -r requirements.txt
python -m streamlit run app.py
```
Откройте адрес из терминала, обычно http://localhost:8501. Оставьте терминал работающим. После установки можно пользоваться start.bat (Windows) или bash start.sh (WSL/Linux). Нужен интернет для первой установки зависимостей; карта-схема внешних карт не требует. Приложение не опубликовано в интернете.

## Что уже работает
- сравнение двух стратегий при общих параметрах;
- базовый / осторожный сценарии, период работы, загрузка, тариф, ресурс флота;
- ограничение перевозок доступным спросом;
- географическая схема 10 пар городов на стратегию, подсказки;
- рейтинг 12 городов, изменение весов и 200 проб устойчивости;
- импорт CSV и проверки формата, экспорт CSV/JSON;
- отдельные функции для подключения моделей команды.

## Данные
`data/cities.csv` — пример формата. Все баллы произвольные, не реальные характеристики городов. Координаты приблизительных центров городов, не аэропортов. Баллы: 35+(i*17+j*23)%61. Критерии шкалы 0..100, больше=лучше. Сами показатели и нормализацию должен подготовить участник №2; веса по умолчанию 25/25/20/15/15 демонстрационные, не результат swing weighting.

`data/routes.csv` — пример двух сетей с хабом Казань. Во встроенном режиме смена хаба пересобирает синтетическую сеть, при импорте файл используется без изменений. Прямые маршруты в демо начинаются в Москве/Екатеринбурге: это упрощённый пример, не реализация всей гипотезы о региональных парах и оборотах. Можно загрузить любые пары городов при наличии их координат.

`source` и `data_status` обязательны. Значение Демо не скрывайте до проверки и замены данных. Источник/метод должен объяснять отдельно спрос и частоты. При загрузке CSV ничего не сохраняется на диск автоматически; используйте скачивание или замените data/cities.csv. CSV UTF-8 с запятыми. Поля city/origin/destination должны точно совпадать.

## Контракт участника №2
`score_cities(cities, weights) -> DataFrame`: сохраняет столбцы городов и добавляет score, сортирует по убыванию. CRITERIA в model.py определяет числовые поля и подписи. Добавьте согласованные критерии (например, удалённость), обновите CSV. При нулевой сумме весов интерфейс показывает ошибку и применяет исходные веса.

## Контракт участника №3
`calculate(routes, **parameters) -> (summary, route_details)`.
summary: strategy, passengers, revenue, net_passengers, share_pct, share_delta_pp, fleet.
route_details: все входные поля плюс flights, capacity, passengers, revenue, net_passengers, effective_load.
Значения strategy: Хаб / Прямые рейсы. Частота weekly_roundtrips — парные обороты, demand_year — годовой спрос в обе стороны, fare_rub — тариф в одну сторону на один участок, block_hours — полёт в одну сторону.

Параметры: seats, load (0..1), fare_factor, demand_factor, months, market, baseline, net_fraction (0..1), daily_hours, reserve (доля), positioning (доля). 52 недели условного года; неполный год масштабируется равномерно, сезонность отсутствует.

Чистый прирост не включает перенос с собственных рейсов. Доля рынка использует заданный годовой знаменатель. 2,7 млн / 108,9 млн — числа за 2025 год из предоставленной справки, а не подтверждённый прогноз 2028. Их необходимо проверить и заменить. Загрузка 85% — ориентир по компании за I полугодие 2025, не прогноз новых маршрутов.

Модель пока считает пассажиров по участкам, не уникальные поездки. Для хаба нужна согласованная методика учёта транзита. Флот — грубая оценка часов, без оборотов, минимального времени стыковок, экипажей, дальности, слотов и реального доступного парка. Выручка не равна прибыли; расходов и субсидий нет. Никакого автоматического победителя приложение не выбирает.
